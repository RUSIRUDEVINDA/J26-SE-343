# Responsible DS evidence verification

User-approved scope: final improvements attachment and follow-up clarifying that the same responsible DS attaches and verifies evidence; no assignment workflow or new role.

Responsibility is narrowly the existing creator of a Saved early officer-assessment request, with fresh current eligible Officer/DS directory membership. No C3 case/jurisdiction relationship is inferred. This covers existing standalone screenings, not arbitrary legacy early-engine rows without ownership. Other DS/applicants cannot read or write; exact Commissioner C4AssessmentReadAll can read only, with current profile/grant and post-read rechecks. Existing complaint authority is unchanged.

Two additive append-only tables: screening_evidence_attachments and screening_evidence_verifications. Both bind RequestId/CreatorActorId through the existing composite request key. Attachments retain concern, bounded filename/type, original bytes (maximum5MiB, PDF/PNG/JPEG/UTF8text), SHA256, idempotency key/hash, authenticated DS and server UTC. Files are untrusted and returned only as authenticated forced downloads with nosniff/sandbox; no OCR, external fetch, preview execution or inference. Limits100attachments/request,1000events/request.

Verification events retain concern, per-concern revision, prior event/status, new Verified/Rejected/MoreInformationRequired status, mandatory20–2000character remarks, bounded references and selected attachment IDs, actor/serverUTC, canonical exact typed event bytes and SHA256. Previous-event composite FK prevents cross-request/concern/creator chains. Unique actor/key, request/concern/revision and prior-event successor. Parameterized short request advisory lock serializes attachment/decision writes, with expected revision and same-key/content replay; changed content409. No lock spans remote ML. Fresh eligibility rechecked before persistence. Actor/time/canonical hash stamped by EF interceptor, normalized to PostgreSQL microseconds. No original screening/request/result updates and no verified-evidence promotion into engines. Baseline manual status Unverified is separate from original Missing/Unverified findings.

Runtime delta: SELECT/INSERT only on these two new tables; no UPDATE/DELETE/DDL/role/account/peer/outbox rights. One additive EF migration, reviewed before isolated and ordinary apply; Down refuses destructive removal. Existing feature gates reused, no new runtime settings/roles/assignment authority. Backup/restore and exact ordinary preflight required before activation. Existing Commissioner report/complaint grants preserved.

GET manual-evidence view and attachments; POST attachment form and verification JSON beneath /api/governance-intelligence/officer-assessments/{request}/manual-evidence. Backend enforces actor/ownership, read-only Commissioner, supported seven concerns, revision, input limits and evidence attachment scope. No invented case IDs. Submitted references remain officer-supplied assertions, not independently verified document truth or legal approval. A DS may attach the evidence personally; verification history records that same actor without pretending independent review occurred.

Git scope: task changes only; exclude secrets, private settings, binaries/dumps/.tmp and unrelated peer changes. Existing large uncommitted feature tree requires explicit staged-diff review before one commit; no push.
