## Explicit state machine

Maintain three independent fields: unchanged classifier state; unchanged existing DS ReviewStatus; NEW HandlingStatus. No inference from category, probabilities, existing Open/UnderReview, or upload/assignment creates a decision.

Initial state is Unassigned (handling revision0) when neither handling nor assignment history exists. For old isolated assignment fixtures without new handling events, derive AssignedToDs from the existing latest assignment, retain handling revision0 and label source LegacyAssignment; do not insert synthetic historical events. Existing ordinary assignment table is not activated, but compatibility must still be tested. New writes always append handling history.

## Access after routing and decisions

Effective access is computed from the latest handling event, falling back only to existing explicit assignment history when NO handling event exists. Never use C3 case-reviewer fallback.

- Direct handling: every DS loses complaint access even if the old assignment row remains the latest assignment event. Historical assignment is retained, not an active permission.
- Active DS handling: only the exact current eligible target/office/assignment event reads or writes permitted complaint actions. Reassignment immediately revokes old DS reads/reviews/retries/history.
- Resolved and Closed: all DS complaint reads/reviews/retries/history are revoked. CentralRead and original applicant retain scoped read access; there is no active responsible officer. Prior assignment/decision actors remain in immutable history.
- Reopened: acting Commissioner owns direct handling; old DS remains denied until a deliberate assignment. A new assignment to a formerly assigned DS is allowed because there is no CURRENT effective DS assignment; same-target rejection still applies within an active DS episode.
- Applicant: original owner only, unchanged original complaint/classification access. New public handling timeline includes status, public summary and UTC; no internal notes/evidence/grant IDs/private officer identities. Existing legacy review-history payloads remain as originally contracted; this proposal does not retroactively rewrite/redact them.
- CentralRead: full internal new action history and current status, original/classification, optional validated case/parcel references. New current-DS action-history view includes current assignment-episode DS actions and public routing/decision summaries; earlier Commissioner-private notes/references are withheld. Existing complaint review JSON remains unchanged.
