# Synthetic proposal generator dependencies

`create_synthetic_proposal.py` is an offline generator, not an OCR result producer or runtime provisioner. Required input: `output/pdf/synthetic-proposal-12-acre/proposal-source.json`. Required installed Python modules: PyMuPDF (`pymupdf`), Pillow (`PIL`) and numpy. It currently requires the Windows Segoe UI regular/bold fonts at the fixed C:/Windows/Fonts paths in the source. That is a platform dependency, not a personal home-directory path. No font binaries are distributed. No API key, database credential or network request is embedded.

Run only after intentionally preparing that output directory, from the workspace root: `python StateLandGovernance/tools/document-intelligence/create_synthetic_proposal.py`. Do not run it over hand-edited generated files without preserving them: it writes the two PDFs, editable HTML, coverage files, expected-field comparison files and artifact-validation.json. It also writes four previews under `.tmp/synthetic-proposal-preview`; `.tmp` must already exist for the current preview mkdir call. The script does not create the ZIP bundle.

The reviewed source is explicitly fictional. Its invalid identity/contact/declaration values must never be promoted to real identity proof. The source, arithmetic assertions, coverage map and comparison values are useful reproducible test material. The generated PDFs are optional upload artifacts; the ZIP and preview images are redundant local outputs. Generating a proposal does not verify a field, complete a requirement, run an engine or establish clearance. The generator was inspected, not executed, in this review.
